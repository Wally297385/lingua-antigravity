# 文本保护领域判据

text_preserve 不承载语义，只保护翻译过程中必须逐字保持的控制符、占位符和格式脚手架；字段、匹配和变更行为以当前 workspace contract 为准。

自定义规则按 JavaScript 正则确定性匹配，`info` 不参与运行时判断。因此最终表达式的每个真实命中都必须可以原样保留。

## 保护资格

先判断结构对象是否必须原样保留，再判断怎样用安全正则表达：

- **必须保护**：已经确认存在必须逐字保持的非语义结构，普通翻译不能稳定保持目标行为。
- **无需保护**：当前对象属于自然语言或其它规则类型，普通翻译能够稳定处理。
- **尚不能判断**：补充调查后仍无法判断；继续尝试按形态、位置或固定前后缀缩小范围，只有无法得到任何安全表达式时才列为需要补充信息。

## 基础发现方向

候选来自控制符、占位符、格式脚手架、相关 warning、已有译文的结构损坏，以及 glossary 路径发现的重复标记。

1. 只扫描原始 `item.src` 并按 `\n` 拆行，不扫描 `name_src`。
2. 以 `new RegExp(source, "giu")` 编译，拒绝非法或零长度表达式。
3. 完整聚合 item、行、片段、`text_type` 和文件分布。
4. 把命中按结构形态分为必须保护、自然语言/其它行为、仍需核验三类。

## 表达式收束阶梯

1. **直接表达**：候选合法、无零长度或危险回溯，且全部真实命中都必须原样保留。
2. **形态分组**：候选同时命中结构与正文时，按标签名、控制符前缀、定界符或 `text_type` 分析差异。
3. **缩小范围或拆分**：为确定安全的结构子集生成更窄正则（如将宽候选 `\{.*\}` 收窄为 `\{[a-z_][a-z0-9_]*\}`）。
4. **保留确定部分**：未知尾部不影响已验证安全的规则，将剩余形态作为独立对象继续调查。
5. **需要补充信息**：结构无法由任何合法、非零长度、不吞正文的正则隔离时，给出缺少的格式事实与手工建议。
