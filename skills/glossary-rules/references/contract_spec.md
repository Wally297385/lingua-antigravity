# LinguaGacha 标准术语表格式规范 (Contract Specification)

本文档为 `@skill(glossary-rules)` 的核心契约参考规范，定义与 LinguaGacha 下游翻译管线完全兼容的 5 字段标准数据结构。

---

## 1. 五字段标准契约 (5-Field Contract)

导出的所有术语条目必须严格遵循以下字段定义：

| 字段 | 类型 | 必填 | 规范与取值要求 |
| :--- | :---: | :---: | :--- |
| `src` | string | 是 | 原文（精确连续字面量，**严禁使用正则元字符**） |
| `dst` | string | 是 | 译文（非空的目标语言固定翻译） |
| `info` | string | 是 | 注释说明（包含角色性别/身份背景/实体类型/必杀技/设定/消歧条件；无特殊说明时为 `""`） |
| `regex` | boolean | 是 | 是否使用正则表达式；**实体术语表中固定为 `false`**（按字面量精确匹配） |
| `case_sensitive` | boolean | 是 | 是否大小写敏感；**默认为 `false`**（不区分大小写），仅当真实大小写冲突需要隔离（如 `May` vs `may`）时设为 `true` |

---

## 2. `info` 字段深度撰写规范（高价值翻译提示与零剧透红线）

运行时，LinguaGacha 将 `src -> dst #info` 组合注入翻译模型。`info` 的唯一核心价值是**为下游翻译模型提供直接、高价值的用词与语法约束（Actionable Hint）**，绝不是作品大纲或剧情剧透！

### 2.1 结构化极简规范
1. **角色条目 (Characters)**：
   - **格式**：`[性别]，[核心身份/职业/人际辈分]`（例：`男性，大园高中男主角`；`女性，三年级学姐`；`女性，理科教师`）；
   - **作用**：性别前置决定第三人称代词（他/她），身份/辈分决定第一人称（俺/僕/私）及第二人称/敬语口吻；
   - **🚫 严禁剧透（硬红线）**：严禁写入生平履历、遇害背景、作案动机、恋分配对或长篇剧情梗概（如 ❌ 严禁出现“被杀害后化为幽灵”、“新山老师的未婚妻”、“协助调查队解开七不可思议”）。
2. **技能 / 招式 / 魔法 / 道具 (Skills & Items)**：
   - **格式**：`[动作类型/攻击距离/属性/形态]`（例：`近战物理剑技`；`远程火属性攻击魔法`；`单手佩剑武器`）；
   - **作用**：指导模型准确选用动作动词和谓语搭配（如“挥出”、“刺向”、“吟唱”、“佩戴”），防止动宾搭配混乱。
3. **专有名词 / 地名 / 设施 / 概念 (Entities & Locations)**：
   - **格式**：`[实体类别]`（例：`学校名`；`商业都市`；`异界迷宫地名`；`校园怪谈代号`）；
   - **作用**：防止模型将设施名误译为人名或普通短语；
   - **🚫 严禁冗余细节**：严禁写入与翻译用词无关的设定说明（如 ❌ 严禁出现“门禁森严需刷学生证”、“第一回探索的迷宫”）。
4. **条件消歧 (Disambiguation)**：
   - 简要指出触发边界（例：`仅在单独作为感叹呼喊时采用本条，其余按普通词翻译`）。

### 2.2 长度与表达红线
- **字数上限**：单条 `info` 严格控制在 **10~20 字以内**；
- **表达原则**：短促、明确、高信息密度，杜绝废话修饰。

---

## 3. 文件格式与导出规范

### 3.1 JSON 规范
- 文件编码必须为 **UTF-8（无 BOM）**；
- 顶级结构必须为 **JSON 数组**，使用 4 空格缩进排版。
- 完整参考范例见：`../examples/lucy_sample.json`。

### 3.2 Excel (XLSX) 规范
- **工作表名称**：必须严格命名为 `"rules"`（大小写敏感）；
- **表头**：首行第 1~5 列分别为 `src`, `dst`, `info`, `regex`, `case_sensitive`；
- **布尔值**：数据行的 `regex` 与 `case_sensitive` 必须为 Excel 原生布尔值 `FALSE`（或在必要时为 `TRUE`）。
