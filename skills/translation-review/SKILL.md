# 译文审查与校对

将审查范围作为证据池，而非把警告误当成全部范围：主动发现候选 → 逐批审查校对 → 残差长尾抽样 → 核对累计结果。

## 一、 核心判断优先级

审查与校对必须遵循以下优先级，后项不得牺牲前项：

1. **用户明确要求**，以及原文的事实、信息量、不确定性、逻辑和表达意图。
2. **术语应用、控制符、占位符、换行、文本保护**及其它工程格式硬约束。
3. **语境能证明的说话人、指代、人物关系、视角、知识边界、语气和剧情连续性**。
4. **目标语言的准确、自然、一致和与原文相称的语言声音**。

> 核心原则：只在语义等价的合理方案之间优化表达；不得为改善情节、人物、节奏或文采而擅自增删、过度解释或重构原文，亦不可把原文特有的歧义、粗粝、不规则或风格化表达生硬磨平。

| 警告类别 | 核心判据与处置原则 |
| :--- | :--- |
| `GLOSSARY` | 随附术语应用给出明确目标且当前译文未落实时，形成变更 |
| `TEXT_PRESERVE` | 能确定正确保护形式（如控制符、代码标签）时，形成变更 |
| `KANA` / `HANGEUL` | 应译出但残留的假名/谚文形成变更；合法的专名、拟声词或符号予以保留 |
| `SIMILARITY` / 阈值警告 | 单独不足以判错；结合语境核实是否存在漏翻、串行或机翻幻觉后按实际错误处置 |

---

## 二、 自适应发现与并发审查流

1. **种子与取样**：
   - 警告项作为首批问题种子。
   - 对无警告区域分散抽样，关注高频隐蔽错误：代词指代漂移、敬语/口吻断裂、否定反转、数量与单位偏差。
2. **并发加速（推荐调用子代理）**：
   - 当待审校内容跨越多个章节或文件体量庞大时，推荐调用 Antigravity 原生子代理（`invoke_subagent`）并行分发各个批次或分卷，极大缩短审查周期。
3. **残差抽样（Residual Check）**：
   - 主流程完成后，从尚未命中的区域执行一次独立长尾抽样，确保无全局性系统偏离后收敛。

---

## 三、 两阶段提交流程（安全红线）

1. **方案呈现（写入确认阶段）**：
   - 逐批整理拟修改项，向搭档清晰汇报：受影响条目、原文、原译文、拟修正译文以及修改依据（如术语纠正、说话人语气对齐）。
2. **获得显式授权后写入**：
   - 搭档确认后，使用 Antigravity 原生文件工具（`replace_file_content`）提交更新，并向搭档核对最终结果。
